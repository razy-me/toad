It transforms the raw Abstract Syntax Tree (AST) generated by the parser and import resolver into an immutable, fully resolved **Layout Tree** of positioned bounding boxes (`LayoutBox`) and computed visual styles (`ComputedStyle`).

## 2. Canvas Dimensions & Aspect Ratio Engine

### 2.1 Canvas Definition & Units
The canvas element acts as the root bounding box. All coordinate systems originate from the canvas top-left corner $(0, 0)$ with $+x$ extending rightward and $+y$ extending downward.

- **Width ($W$) and Height ($H$)**: Specified in integer or floating-point pixel units (`px`). If unitless, pixels are assumed.
- **Percentage Units (`%`)**: Top-level percentages evaluate directly against canvas dimensions ($w = W \times \frac{p}{100}$, $h = H \times \frac{p}{100}$). Inside groups, percentages evaluate against the parent group's resolved bounding box.

### 2.2 GCD Aspect Ratio Calculation
To produce standard photographic/display aspect ratios (e.g. `16:9`, `1:1`, `4:5`, `21:9`), the math engine computes the Greatest Common Divisor (GCD) using the Euclidean algorithm on integer dimensions:

$$\gcd(a, 0) = |a|$$
$$\gcd(a, b) = \gcd(b, a \pmod b)$$

```typescript
export function computeGcd(a: number, b: number): number {
  let x = Math.abs(Math.round(a));
  let y = Math.abs(Math.round(b));
  while (y !== 0) {
    const t = y;
    y = x % y;
    x = t;
  }
  return x === 0 ? 1 : x;
}

export function computeAspectRatio(width: number, height: number): { ratioX: number; ratioY: number; ratioString: string } {
  const gcd = computeGcd(width, height);
  const ratioX = Math.round(width) / gcd;
  const ratioY = Math.round(height) / gcd;
  return {
    ratioX,
    ratioY,
    ratioString: `${ratioX}:${ratioY}`
  };
}
```

### 2.3 Canvas Scale Factor Resolution
Raster export supports scale multipliers ($S \in \{1, 2, 4\}$):
- $W_{\text{pixel}} = \text{round}(W \times S)$
- $H_{\text{pixel}} = \text{round}(H \times S)$
- Scale factor scales all computed vertex coordinates, line widths, and font sizes linearly when rendering to raster buffers while preserving exact relative proportions.

## 3. Bounding Box Computation Specifications

Every element in `TOAD` generates a concrete `LayoutBox`:
```typescript
export interface LayoutBox {
  x: number;      // Absolute canvas X
  y: number;      // Absolute canvas Y
  w: number;      // Bounding box width
  h: number;      // Bounding box height
  localX?: number; // Relative to parent group
  localY?: number; // Relative to parent group
}
```

### 3.1 `rect`
- **Inputs**: `size: <w> <h>` or `width: <w>; height: <h>;`, `border-radius: <r>`, `stroke-width: <sw>`.
- **Bounding Box**:
  - $w = \text{resolveWidth}(size.w)$
  - $h = \text{resolveHeight}(size.h)$
- **Corner Radii**: Clamped such that $r \le \min(w/2, h/2)$. Radius does not enlarge the geometric bounding box.
- **Stroke Alignment**: Nominal layout bounding box remains $[x, y, w, h]$. If outer stroke is applied, visual bounds extend by $sw$, but relational layout anchors bind to the nominal outer geometry.

### 3.2 `circle`
- **Inputs**: `radius: <r>` or `r: <r>` or `size: <d> <d>`.
- **Bounding Box**:
  - If radius $r$ is specified: $w = 2r$, $h = 2r$.
  - If positioned by top-left: $x = pos.x, y = pos.y$.
  - If positioned by center: $x = pos.x - r, y = pos.y - r$.

### 3.3 `polygon`
- **Inputs**: `points: Array<[x: number, y: number]>`, optional `size: <w> <h>`.
- **Center-Relative Local Frame**:
  - Points $P_i = (x_i, y_i)$ are specified relative to the polygon's geometric center $(0,0)$.
  - Natural Extrema:
    $$x_{\min} = \min_{i}(x_i), \quad x_{\max} = \max_{i}(x_i)$$
    $$y_{\min} = \min_{i}(y_i), \quad y_{\max} = \max_{i}(y_i)$$
    $$w_{\text{natural}} = x_{\max} - x_{\min}, \quad h_{\text{natural}} = y_{\max} - y_{\min}$$
  - If explicit `size: W H` is provided, scaling factors are:
    $$s_x = \frac{W}{w_{\text{natural}}}, \quad s_y = \frac{H}{h_{\text{natural}}}$$
    Final bounding box has width $W$ and height $H$.
  - If no explicit size is given, bounding box has width $w_{\text{natural}}$ and height $h_{\text{natural}}$.

### 3.4 `text`
- **Inputs**: `content: string`, `font-size`, `font-family`, `font-weight`, `font-style`, `line-height`, optional explicit `size.w`.
- **Bounding Box**: Exact metrics measured via headless Skia (`@napi-rs/canvas`). See Section 4 for complete measurement and line-wrap specification.

### 3.5 `image`
- **Inputs**: `src: string`, `size: <w> <h>`, `fit: "fill" | "cover" | "contain" | "none"`.
- **Bounding Box**: $[x, y, w, h]$ allocated according to declared `size`.
- **Fit Geometry Computation**:
  Let natural image dimensions be $(W_{img}, H_{img})$ and container box be $(W_{box}, H_{box})$:
  - `fill`: Image stretches to exactly $W_{box} \times H_{box}$.
  - `contain`: Scale $s = \min(W_{box}/W_{img}, H_{box}/H_{img})$. Rendered rect is $s W_{img} \times s H_{img}$, centered inside $[x, y, W_{box}, H_{box}]$.
  - `cover`: Scale $s = \max(W_{box}/W_{img}, H_{box}/H_{img})$. Rendered rect is $s W_{img} \times s H_{img}$, clipped to $[x, y, W_{box}, H_{box}]$.
  - `none`: Rendered at $W_{img} \times H_{img}$ at $[x, y]$, clipped to container box.

### 3.6 `group`
- **Inputs**: `children: ASTNode[]`, optional `size: <w> <h>`.
- **Bounding Box Resolution**:
  - If children are positioned relative to canvas or group origin, the group's bounding box is the minimum enclosing bounding rectangle (AABB) of all its resolved children:
    $$x_{\min} = \min_{c \in \text{children}}(c.x), \quad y_{\min} = \min_{c \in \text{children}}(c.y)$$
    $$x_{\max} = \max_{c \in \text{children}}(c.x + c.w), \quad y_{\max} = \max_{c \in \text{children}}(c.y + c.h)$$
    $$x = x_{\min}, \quad y = y_{\min}, \quad w = x_{\max} - x_{\min}, \quad h = y_{\max} - y_{\min}$$
  - If a group has an explicit `size: W H` and `at: X Y`, children position with offset $(X, Y)$ and the group's box is explicitly $[X, Y, W, H]$.
  - Empty group: $[0, 0, 0, 0]$.

### 3.7 `grid`
- **Inputs**: `columns: number`, `gap: number | [gapX, gapY]`, `cell-size: [w, h]`, `children: ASTNode[]`.
- **Bounding Box**: See Section 8 for complete tile grid equations.

## 4. Headless Skia Text Measurement & Layout Engine

### 4.1 Measurement Mechanism (`@napi-rs/canvas`)
Text measurement uses an offscreen Skia CanvasRenderingContext2D instance:

```typescript
import { createCanvas } from '@napi-rs/canvas';

const measureCanvas = createCanvas(1, 1);
const measureCtx = measureCanvas.getContext('2d');
```

#### Font String Formatting
The font descriptor string must conform to CSS font shorthand:
$$\text{fontString} = `\$\{fontStyle\}\ \$\{fontWeight\}\ \$\{fontSize\}\text{px}\ "\$\{fontFamily\}"`$$
*Example*: `normal 700 24px "Inter"`, `italic 400 16px "Roboto"`

### 4.2 Metrics Extraction & Baseline
For any measured line $L$:
```typescript
measureCtx.font = fontString;
measureCtx.textBaseline = 'alphabetic';
const metrics = measureCtx.measureText(L);
```

- **Advance Width**: `metrics.width`
- **Ink Ascent**: `metrics.actualBoundingBoxAscent` (distance from baseline up to highest pixel)
- **Ink Descent**: `metrics.actualBoundingBoxDescent` (distance from baseline down to lowest pixel)
- **Ink Left**: `metrics.actualBoundingBoxLeft`
- **Ink Right**: `metrics.actualBoundingBoxRight`
- **Typographic Line Height**: Default is $1.2 \times \text{fontSize}$ unless `line-height` is specified (e.g. `line-height: 1.5` $\to 1.5 \times \text{fontSize}$, or `line-height: 32px` $\to 32$).

### 4.3 Auto-Wrap Rules (Strict Specification)
**Rule**: Auto-wrapping is ONLY activated if `size.w` (or `width`) is explicitly defined on the text element.

#### Case A: No Explicit `size.w` (Single / Multi-line via Explicit `\n` Only)
1. Split text on newline characters: `lines = content.split('\n')`.
2. Measure each line independently: $w_i = \text{measureCtx.measureText}(lines[i]).\text{width}$.
3. Total Box Width: $W = \max_{i}(w_i)$.
4. Total Box Height: $H = \text{lines.length} \times \text{lineHeight}$.

#### Case B: Explicit `size.w` Defined (Greedy Word Wrap Engine)
1. Split content into paragraphs on `\n`.
2. For each paragraph:
   - Split paragraph into tokens by whitespace: `tokens = paragraph.split(/\s+/)`.
   - Greedily accumulate tokens into the current line while:
     $$\text{measureText}(\text{currentLine} + \text{" "} + \text{token}).\text{width} \le \text{explicitWidth}$$
   - If adding the next token exceeds `explicitWidth`:
     - Push `currentLine` to wrapped lines list.
     - Start a new line with the current token.
   - If a single isolated token exceeds `explicitWidth`, keep the token on its own line (do not drop or loop infinitely).
3. Total Box Width: $\text{explicitWidth}$.
4. Total Box Height: $\text{wrappedLines.length} \times \text{lineHeight}$.

```typescript
export interface TextLayoutResult {
  lines: string[];
  width: number;
  height: number;
  lineHeight: number;
  fontSize: number;
  fontFamily: string;
}

export function layoutText(
  content: string,
  style: {
    fontFamily: string;
    fontSize: number;
    fontWeight?: string | number;
    fontStyle?: string;
    lineHeight?: number;
    explicitWidth?: number;
  },
  ctx: CanvasRenderingContext2D
): TextLayoutResult {
  const fontSize = style.fontSize;
  const fontWeight = style.fontWeight || 400;
  const fontStyle = style.fontStyle || 'normal';
  const fontFamily = style.fontFamily || 'sans-serif';
  const lineHeight = style.lineHeight ? (style.lineHeight < 5 ? style.lineHeight * fontSize : style.lineHeight) : Math.round(fontSize * 1.25);

  ctx.font = `${fontStyle} ${fontWeight} ${fontSize}px "${fontFamily}"`;

  const paragraphs = content.split('\n');
  const finalLines: string[] = [];

  if (style.explicitWidth === undefined || style.explicitWidth <= 0) {
    // No auto-wrap
    let maxWidth = 0;
    for (const para of paragraphs) {
      finalLines.push(para);
      const w = ctx.measureText(para).width;
      if (w > maxWidth) maxWidth = w;
    }
    return {
      lines: finalLines,
      width: Math.ceil(maxWidth),
      height: finalLines.length * lineHeight,
      lineHeight,
      fontSize,
      fontFamily
    };
  }

  // Auto-wrap active
  const maxW = style.explicitWidth;
  for (const para of paragraphs) {
    if (para.trim() === '') {
      finalLines.push('');
      continue;
    }
    const words = para.split(/\s+/);
    let currentLine = words[0];

    for (let i = 1; i < words.length; i++) {
      const candidate = `${currentLine} ${words[i]}`;
      if (ctx.measureText(candidate).width <= maxW) {
        currentLine = candidate;
      } else {
        finalLines.push(currentLine);
        currentLine = words[i];
      }
    }
    finalLines.push(currentLine);
  }

  return {
    lines: finalLines,
    width: maxW,
    height: finalLines.length * lineHeight,
    lineHeight,
    fontSize,
    fontFamily
  };
}
```

## 5. `currentColor` Static Resolution Pass

### 5.1 Purpose & Photoshop Layer Cleanliness
In modern design workflows, `currentColor` represents the inherited typographic foreground color. To ensure that generated Photoshop `.psd` layers and raster drawing passes have pure, unpolluted color channels without runtime lookups, the layout engine performs a static resolution pass down the AST hierarchy before generating render commands.

### 5.2 Tree Cascade Algorithm
1. The canvas root initializes with default active color $C_{\text{canvas}} = \text{canvas.color} \parallel \text{"#000000"}$.
2. Traverse top-down through the element tree:
   - For node $N$ with parent active color $C_{\text{parent}}$:
     - If $N$ declares an explicit `color: <val>`, $C_{\text{active}} = \text{normalizeColor}(val)$.
     - Else, $C_{\text{active}} = C_{\text{parent}}$.
   - For every color property on $N$ (`fill`, `stroke`, `shadow.color`, `gradient.stops[i].color`):
     - If property equals `"currentColor"`, replace it with $C_{\text{active}}$.
3. Store resolved colors directly on the node's `ComputedStyle`.

```typescript
export function resolveCurrentColorPass(node: ASTNode, inheritedColor = '#000000'): void {
  const activeColor = node.color ? normalizeColor(node.color) : inheritedColor;
  node.computedColor = activeColor;

  if (node.fill === 'currentColor') node.fill = activeColor;
  if (node.stroke === 'currentColor') node.stroke = activeColor;
  if (node.shadow && node.shadow.color === 'currentColor') {
    node.shadow.color = activeColor;
  }
  if (node.gradient && node.gradient.stops) {
    for (const stop of node.gradient.stops) {
      if (stop.color === 'currentColor') {
        stop.color = activeColor;
      }
    }
  }

  if (node.children && Array.isArray(node.children)) {
    for (const child of node.children) {
      resolveCurrentColorPass(child, activeColor);
    }
  }
}
```

## 6. Relational Positioning Engine & Math Formulas

The `at:` property allows declarative positioning of elements relative to canvas coordinates, parents, or sibling element IDs (`#id`).

### 6.1 Positioning Syntax & Semantics
| Syntax Pattern | Math Formulation (Target $T$, Subject $S$, Offset $(\Delta x, \Delta y)$) | Description |
| :--- | :--- | :--- |
| `at: <x>px <y>px` | $S.x = x$, $S.y = y$ | Absolute canvas positioning |
| `at: <x>% <y>%` | $S.x = \frac{x}{100} \cdot W_{\text{canvas}}$, $S.y = \frac{y}{100} \cdot H_{\text{canvas}}$ | Relative to canvas / container |
| `at: right of #id` | $S.x = T.x + T.w + \Delta x$, $S.y = T.y + \Delta y$ | Placed immediately to the right of $T$ |
| `at: left of #id` | $S.x = T.x - S.w - \Delta x$, $S.y = T.y + \Delta y$ | Placed immediately to the left of $T$ |
| `at: below #id` / `at: bottom of #id` | $S.x = T.x + \Delta x$, $S.y = T.y + T.h + \Delta y$ | Placed immediately below $T$ |
| `at: above #id` / `at: top of #id` | $S.x = T.x + \Delta x$, $S.y = T.y - S.h - \Delta y$ | Placed immediately above $T$ |
| `at: center of #id` | $S.x = T.x + \frac{T.w - S.w}{2} + \Delta x$, $S.y = T.y + \frac{T.h - S.h}{2} + \Delta y$ | Centered horizontally and vertically inside $T$ |
| `at: inside #id` | $S.x = T.x + \Delta x$, $S.y = T.y + \Delta y$ | Nested inside top-left of $T$ with offset |

### 6.2 Offset Handling
Offsets can be specified as:
- Additional coordinate pair: `at: right of #header offset 12px 24px` $\to \Delta x = 12, \Delta y = 24$.
- Inline addition: `at: below #hero + 30px` $\to \Delta x = 0, \Delta y = 30$.

### 6.3 Position Fallback & Warning Rules
1. If an element does NOT specify an `at:` property:
   - Position defaults to $(0, 0)$.
   - Compiler emits diagnostic warning:  
     `[WARN] Element '${element.id || element.type}' has no 'at:' position specified. Defaulting to (0, 0).`
2. If an element references an unknown `#id`:
   - Position falls back to $(0, 0)$.
   - Compiler emits diagnostic warning/error:  
     `[WARN] Element '${element.id}' references missing relational anchor '#${targetId}'. Defaulting to (0, 0).`

## 7. Dependency Graph & Topological Solver (`src/parser/dependencyGraph.ts`)

When elements use relational positioning (`at: right of #id`), their layout boxes cannot be computed until their reference targets have known positions and dimensions.

### 7.1 Directed Acyclic Graph (DAG) Model
- **Nodes ($V$)**: Every element with an `id` (or synthetic index ID).
- **Directed Edges ($E$)**: Edge $(A, B)$ represents "$A$ depends on $B$" ($B \to A$ in resolution order, where $B$ must be resolved before $A$).

### 7.2 Cycle Detection & Topological Sort Algorithm
The solver uses Depth-First Search with 3-color node state tracking:
- `WHITE (0)`: Unvisited
- `GRAY (1)`: Currently exploring (on current recursion stack)
- `BLACK (2)`: Fully resolved and placed in topological order

```typescript
export enum VisitState {
  WHITE = 0,
  GRAY = 1,
  BLACK = 2
}

export interface DependencyNode {
  id: string;
  element: ASTNode;
  dependencies: string[]; // List of element IDs this element depends on
}

export class DependencyGraph {
  private nodes = new Map<string, DependencyNode>();

  public addNode(id: string, element: ASTNode, dependencies: string[]): void {
    this.nodes.set(id, { id, element, dependencies });
  }

  public resolveOrder(): ASTNode[] {
    const state = new Map<string, VisitState>();
    const order: ASTNode[] = [];
    const recursionStack: string[] = [];

    for (const id of this.nodes.keys()) {
      state.set(id, VisitState.WHITE);
    }

    const visit = (id: string) => {
      const currentState = state.get(id);
      if (currentState === VisitState.GRAY) {
        const cyclePath = [...recursionStack.slice(recursionStack.indexOf(id)), id].join(' -> ');
        throw new Error(`Cyclic layout dependency detected: ${cyclePath}`);
      }
      if (currentState === VisitState.BLACK) {
        return;
      }

      state.set(id, VisitState.GRAY);
      recursionStack.push(id);

      const node = this.nodes.get(id);
      if (node) {
        for (const depId of node.dependencies) {
          if (this.nodes.has(depId)) {
            visit(depId);
          } else {
            console.warn(`[WARN] Relational dependency '#${depId}' not found for element '#${id}'.`);
          }
        }
      }

      recursionStack.pop();
      state.set(id, VisitState.BLACK);
      if (node) {
        order.push(node.element);
      }
    };

    for (const id of this.nodes.keys()) {
      if (state.get(id) === VisitState.WHITE) {
        visit(id);
      }
    }

    return order;
  }
}
```

## 8. Polygon Local & Center-Relative Coordinate Space

### 8.1 Center-Relative Definition
Polygons in `TOAD` are defined with vertices relative to the polygon's geometric center $(0,0)$.
*Example*:
```
polygon Arrow {
  points: [0, -40], [30, 20], [-30, 20];
  size: 120px 80px;
}
```

### 8.2 Vertex Mapping to Canvas Space
1. Given raw polygon points $P_i = (x_i, y_i)$ for $i \in [0, N-1]$.
2. Compute raw bounds:
   $$x_{\min} = \min(x_i), \quad x_{\max} = \max(x_i)$$
   $$y_{\min} = \min(y_i), \quad y_{\max} = \max(y_i)$$
   $$W_{\text{raw}} = x_{\max} - x_{\min}, \quad H_{\text{raw}} = y_{\max} - y_{\min}$$
3. Given resolved bounding box $[X, Y, W, H]$:
   - Center of bounding box is $(C_x, C_y) = (X + W/2, Y + H/2)$.
   - Scale multipliers:
     $$k_x = W_{\text{raw}} > 0 ? \frac{W}{W_{\text{raw}}} : 1$$
     $$k_y = H_{\text{raw}} > 0 ? \frac{H}{H_{\text{raw}}} : 1$$
4. Canvas vertex coordinates $V_i = (X_{c, i}, Y_{c, i})$:
   $$X_{c, i} = C_x + x_i \cdot k_x$$
   $$Y_{c, i} = C_y + y_i \cdot k_y$$

## 9. Uniform Tile Grid Layout Model

### 9.1 Grid Model Properties
- `columns`: Fixed integer column count $C \ge 1$.
- `gap`: Horizontal gap $g_x$ and vertical gap $g_y$ (if single value $g$, $g_x = g_y = g$).
- `cell-size`: Fixed width and height for every grid tile $[w_{\text{cell}}, h_{\text{cell}}]$.
- `children`: List of $N$ elements laid out in row-major order (left-to-right, top-to-bottom).

### 9.2 Cell Coordinate Equations
For child at index $i \in [0, N-1]$:
$$\text{row} = \lfloor i / C \rfloor$$
$$\text{col} = i \pmod C$$
$$x_i = X_{\text{grid}} + \text{col} \times (w_{\text{cell}} + g_x)$$
$$y_i = Y_{\text{grid}} + \text{row} \times (h_{\text{cell}} + g_y)$$
$$w_i = w_{\text{cell}}$$
$$h_i = h_{\text{cell}}$$

### 9.3 Total Grid Container Dimensions
$$\text{Total Rows } R = \lceil N / C \rceil \quad (\text{if } N = 0 \implies R = 0)$$
$$W_{\text{grid}} = C \cdot w_{\text{cell}} + (C - 1) \cdot g_x$$
$$H_{\text{grid}} = R \cdot h_{\text{cell}} + (R - 1) \cdot g_y \quad (\text{if } R > 0 \text{ else } 0)$$

If outer grid size $W_{\text{grid}}$ is specified explicitly, $w_{\text{cell}}$ is inferred via:
$$w_{\text{cell}} = \frac{W_{\text{grid}} - (C - 1) \cdot g_x}{C}$$

## 12. Edge Cases

| # | Feature | Input | Observed / Required Behavior |
|---|---------|-------|------------------------------|
| 1 | Canvas GCD | `size: 1920px 1080px` | $\gcd(1920, 1080) = 120 \implies 16:9$. |
| 2 | Canvas GCD | `size: 1080px 1350px` (Instagram portrait) | $\gcd(1080, 1350) = 270 \implies 4:5$. |
| 3 | Canvas GCD | `size: 1200px 630px` (OG image) | $\gcd(1200, 630) = 30 \implies 40:21$. |
| 4 | Canvas GCD | `size: 0px 0px` or negative dimensions | Rejects invalid canvas size; fallback to `1:1` with error. |
| 5 | Relational Cycle | `#a` at `right of #b`, `#b` at `below #a` | Topological DFS detects cycle; throws `Cyclic layout dependency detected: #a -> #b -> #a`. |
| 6 | Relational Missing ID | `#btn` at `below #ghost_header` | Emits `[WARN] Relational dependency '#ghost_header' not found`, falls back to $x=0, y=0$. |
| 7 | Text Measurement | `content: "Hello\nWorld"`, no `size.w` | Split into 2 lines; width is $\max(w_1, w_2)$, height is $2 \times \text{lineHeight}$. No word wrapping. |
| 8 | Text Word Wrap | `content: "Superlongwordwithoutspaces"`, `size.w: 50px` | Single word placed on line without splitting mid-word; box width is 50px, single line height. |
| 9 | Text Auto-Wrap Off | Long single paragraph (1000px wide) without `size.w` | Remains single line of width 1000px; does NOT wrap. |
| 10 | `currentColor` Deep Cascade | Root `#000` $\to$ Group `color: #00f` $\to$ Nested Group (no color) $\to$ Rect `fill: currentColor` | Rect `fill` statically resolves to `#00f`. |
| 11 | `currentColor` Unset Root | Root node has `fill: currentColor` without parent or canvas color | Statically resolves to fallback `#000000`. |
| 12 | Polygon Scaling | Center-relative points $[0,-50], [50,50], [-50,50]$ with `size: 200px 200px` | Natural size $100 \times 100$ scaled by $2.0 \times 2.0$; vertices become $[0,-100], [100,100], [-100,100]$ relative to center. |
| 13 | Grid Overflow | Grid with `columns: 3`, total children = 7 | Rows $R = \lceil 7 / 3 \rceil = 3$. Row 0: cols 0,1,2; Row 1: cols 0,1,2; Row 2: col 0 (cols 1,2 empty). |
| 14 | Grid Empty | `grid { columns: 4; children: []; }` | Returns $0 \times 0$ box; no error. |
| 15 | Group Bounding Box | Group with child 1 at $(100, 100, 50, 50)$ and child 2 at $(200, 300, 80, 20)$ | Group box evaluates to $x=100, y=100, w = (280 - 100) = 180, h = (320 - 100) = 220$. |
| 16 | Gradient Stops | 3 stops with colors `[#f00, #0f0, #00f]` and no positions | Positions resolved to $[0.0, 0.5, 1.0]$. |
| 17 | Gradient Stops | 4 stops with only first (0.0) and last (1.0) defined | Middle two stops resolved to $0.333$ and $0.667$. |
| 18 | Top-Level No Position | `rect { size: 100px 100px; }` without `at:` | Emits warning and positions at $(0, 0)$. |
